# 通用方法论：机型无关的六步

> 目标读者：想复活自己那台运营商盒子的人，以及**替他执行的 AI**。
> 本文只讲与具体型号无关的部分；型号相关的答案在 `cases/<机型>/` 里。

## 0. 心智模型：这类机器为什么"变砖"

运营商定制盒子的"不可用"通常是三件事叠在一起：

1. **HOME 被登录引导器占据** —— 一个带 `CATEGORY_HOME` 的运营商应用（本项目案例里是
   `com.sumavision.loader`），开机即前台，没有业务账号就停在登录页。
2. **一圈看门狗 / 广告 / TMS 远管应用** —— 其中**混着官方调试开关**，肉眼分不清哪个是哪个。
3. **网络 ADB 不持久** —— `persist.sys.usb.config=none`，adbd 开机根本不启动，
   要从遥控器某个隐藏入口手动拉起，一重启就失联。

所以真正的目标只有两个：**A 让 HOME 落到用户桌面**，**B 让 ADB 每次开机自动在**。
其余（去广告、冻结包、精简系统）都是次要的，而且正是它们导致变砖和失联。

## 1. 六步流程

### 第 1 步：侦察（10 分钟，决定后面全部设计）

```bash
adb connect <盒子IP>:5555
adb shell getprop ro.product.model; adb shell getprop ro.board.platform
adb shell getprop ro.build.version.release      # 安卓版本决定 API 下限
adb shell getenforce                             # ← 最关键的一行
adb shell "su 0 id"                              # 有没有开放 root，su 是什么语法
adb shell "cmd package query-activities -a android.intent.action.MAIN -c android.intent.category.HOME"
adb shell "pm list packages -s | grep -iE 'cmcc|chinamobile|telecom|cn|sumavision|huawei|zte'"
```

要拿到五个答案并写进你的案例文档：

| 问题 | 为什么决定成败 |
| --- | --- |
| `getenforce` = ? | **Permissive** → 普通应用可直接写系统属性、`ctl.restart adbd`，免 root 路径成立；Enforcing 就得另找路 |
| root 语法 | `su 0 <cmd>` 还是 `su -c`；su 是否按调用方白名单拒绝应用身份 |
| HOME 候选有几个、谁是登录页 | 决定"替身"还是"优先级"还是"两者都要" |
| 官方调试入口在哪 | **这是你唯一的自救通道，必须写进文档最显眼处** |
| `adb install` 能不能用 | 很多这类机器 streamed install 是坏的，要 push + `pm install` |

### 第 2 步：定位资源，不要联网下载

机器自己的卡刷包（`update.zip`）里就有原厂 APK、桌面 APK。
链路是通用的：`update.zip → system.new.dat.br --brotli--> system.new.dat
→ (transfer.list 拼块) → system.img(ext4) → 纯 python 读 ext4 取文件`。
见 `scripts/extract_apk_from_rom.py`（通用，可直接复用）。

同时用 `aapt dump xmltree <apk> AndroidManifest.xml` 看清目标包的组件：
**如果它只有一个入口 Activity + 空 Application，就走"替身"路线**（第 4 步），
不需要 apktool / smali / 重打包，工具链省一整层。

### 第 3 步：先做一个用户自己的桌面入口

装上任一合法获取的电视桌面（当贝、BBLL、ATV  launcher 等），
`pm install -r` 之后**立刻 `am start` 打开一次**（见 §3 坑 B1）。

### 第 4 步：目标 A —— 让登录页物理消失（替身启动器）

自建一个**同包名、同类名**的迷你 APK（`src/loaderstub/`）：

```java
onCreate: startActivity(用户桌面); finish();
```

Manifest 里给它 HOME intent-filter 加 `android:priority="1"`（其它候选通常是 0）。
原位替换进 `/system`：备份原版 → `rm -rf` 同目录 `oat/`（旧 odex 校验会出问题）→
`chmod 644` / `chown 0:0` / `restorecon` / `sync`。

为什么不用 `cmd package set-home-activity`：这类 ROM 上 preferred activity 记录
**可能被系统持续作废**（日志 `Result set changed, dropping preferred activity`）。
`android:priority` 是包扫描期属性，不依赖运行时记录，才是稳的。

### 第 5 步：目标 B —— 免 root 固化网络 ADB

三层冗余，动态层是主力（`src/tvfix/`，BOOT_COMPLETED 后延时执行）：

```java
SystemProperties.set("service.adb.tcp.port", "5555");
SystemProperties.set("persist.adb.tcp.port", "5555");
SystemProperties.set("ctl.restart", "adbd");     // Permissive 下 init 真的会执行
Settings.Global.putInt(adb_enabled, 1);          // priv-app + 白名单拿 WRITE_SECURE_SETTINGS
```

静态层：`/system/build.prop` 追加 `service.adb.tcp.port=5555`（属性只管端口，
**没人启动 adbd 时它单独无效**）。应用层兜底：桌面上留一个"开 ADB"按钮，
失联时人在电视前就能自助。

为什么装成 priv-app：防误删（/data 清了 /system 还在）、拿白名单权限、常驻用户入口。

### 第 6 步：重启前检查清单 → 重启验收

清单（每条都要真跑命令验证，不要凭记忆）：

1. `getprop service.adb.tcp.port` = 5555
2. `/system/build.prop` 含该行（shell 常常读不了 build.prop，用 `su 0 grep`）
3. 自启应用**已被打开过一次**（非 stopped 状态）
4. priv-app 副本在位、权限白名单 xml 在位
5. 原版 APK 备份在 `/data/local/tmp/` **且已拷回电脑**（/data 会被卡刷清掉）
6. `sync`
7. 电视前有人、遥控器在手（万一要手动开调试）

验收要"零人工"：重启后轮询

```bash
adb wait-for-device shell getprop sys.boot_completed     # =1
adb shell "dumpsys window | grep mCurrentFocus"          # = 你的桌面
adb shell getprop init.svc.adbd                          # = running
adb shell "pm list packages -d"                          # 只有出厂自禁的包 = 零冻结
```

## 2. 决策树：我该怎么改

```
getenforce?
├── Permissive → 应用层写属性 + ctl.restart，免 root 全案成立（本项目路线）
└── Enforcing
    ├── 有开放 root（su 0 id = uid 0）→ 只做 /system 文件级改动，放弃应用提权层
    └── 无 root → 只能装用户级 APK：桌面用 priority 抢 HOME；
                  ADB 走"出厂调试入口 + 每次开机人工/遥控器一次"，别再折腾
HOME 候选只有一个入口 Activity?
├── 是 → 同包名替身（最干净，8KB，签名自由）
└── 否（有 service/receiver）→ apktool 改 smali 里做验证的那段，或保留原包只加优先级更高的 HOME 候选
adb install 可用?
├── 否 → adb push /data/local/tmp + pm install -r
└── 是 → 正常流程，但仍建议装成 priv-app 防删
```

## 3. 可迁移的坑（每一条都有人付过代价）

- **B1 刚 `pm install` 的应用处于 stopped 状态，BOOT_COMPLETED 全部丢弃** —— 装完必须 `am start` 一次。这是最常见的"我明明装了自启为什么没跑"。
- **B2 `/system/etc/init/` 下运行期新增的 .rc 往往不生效**（init 只在启动时解析；部分 ROM 干脆不扫这个目录）。固化"开机做某事"别押这条。
- **B4 绝不在 `adb shell` 会话里 `stop adbd`** —— adbd 一死，挂在它下面的 shell/su 一起陪葬，`start adbd` 永远执行不到，当场失联。要重启就从应用进程里做，或 `nohup sh -c 'stop adbd; start adbd' &`。
- **A1 su 可能自带调用方白名单**：`chmod 4755` 让文件可执行了，su 仍打印 `su: not allowed` 拒绝应用身份。别在这条路上继续投入。
- **C1 `set-home-activity` 打印 Success ≠ 生效**，而且 `resolve-activity` 的显示会误导你；**真实遥控器 HOME 键行为才是唯一验收标准**。
- **D5 诊断必须落文件**：盒子连截屏都麻烦，UI 上的输出转瞬即逝。让应用把每步写进 `files/boot.log`、脚本写进 `/data/local/tmp/*.log`，adb 一拉就见真相。v3 加了日志之后，一行 `su: not allowed` 推翻了之前全部假设。

## 4. 风险控制红线

- 一切改动**可原路还原**：替换文件（留备份）优于重刷分区；
- **不碰 boot / recovery**：Magisk 路线在这类冷门上电平台上资料极少，变砖风险不成比例；
- 不动 `init.<board>.rc` 等开机关键 rc —— 语法错误 = 开不了机；
- 出厂自带的自救入口（设置/遥控热键/官方调试密码）**一个字都不动**；
- 动手前先确认你有救砖手段（U盘 recovery 卡刷包、UART）。见 [DISCLAIMER.md](../../DISCLAIMER.md)。
