# AI 执行手册：把这套流程交给 agent

本项目是**一个 AI 在一次真实会话里全程完成**的（见 `cases/M401H/`）。
这份文档把当时缺了就会出错的部分固化成模板：启动 prompt、回合脚本、验收门禁。

## 1. 启动 prompt 模板（复制粘贴用）

```
我要复活一台运营商定制安卓机顶盒，请按 tvbox-revival 仓库的方法论执行，
先读 AGENTS.md 和 docs/00-通用方法论.md，再回答我的问题。

设备信息：
- 型号：<如 M401H>，运营：<移动/电信/联通>
- 现象：开机强制进入运营商登录页，无业务账号，等于砖
- 网络 ADB 当前状态：<已开 / 需从遥控器开>，盒子 IP <ip>
- 官方调试入口（我实测可用）：<例如 设置→密码10086→其他→左键32下>
- 我手上的资源：<卡刷包 update.zip 路径 / 无>
- 我想要的桌面：<当贝 / 其他 APK 路径>

我的三条要求（不可协商）：
1. 不删除、不冻结任何运营商应用，只允许提优先级和同包名替身；
2. 不碰 boot/recovery，不装 Magisk；
3. 每次重启前，先把检查清单逐条跑给我看，并且告诉我要不要我在电视前待命。

第一步：只做侦察，把 getenforce / su 语法 / HOME 候选 / 调试入口 / adb install 是否可用
这五个答案列成表格给我，然后给出你的方案与风险，先不要改动设备。
```

**为什么最后那句"先不要改动设备"很重要**：让 agent 先交侦察结论，人看一眼机型是否被认对，
比事后回滚便宜两个数量级。

## 2. 阶段门禁（每阶段"通过条件"必须真跑命令）

| 阶段 | 通过条件（可测量） |
| --- | --- |
| 侦察 | 五个关键答案成表；`getenforce` 明确；HOME 候选清单打印出来 |
| 资源 | 提取出的 APK 用 `aapt dump badging` 能读出包名与 HOME Activity |
| 桌面上位 | 遥控器按 HOME 键，屏幕真落到你的桌面（**不看 resolve-activity 的输出**） |
| 登录页消失 | 重启后 `dumpsys window \| grep mCurrentFocus` = 你的桌面，且无人按过任何键 |
| ADB 固化 | 重启后 `getprop init.svc.adbd` = running，`adb connect` 一次通 |
| 终验 | `pm list packages -d` 只列出厂自禁包（证明零冻结）；全程零人工操作 |

## 3. 常见"agent 会自己挖坑"的地方

- 拿到 root 就兴奋，把可疑的运营商包全冻了 → **违反铁律 1**，直接导致失联。
  正确做法：先只做侦察与备份，把每个包的**真实作用**搞清（本项目里被误判为看门狗的
  `adbswitch` 恰恰是调试开关本体）。
- 用 `cmd package set-home-activity` 当成功标志 → 这类 ROM 会秒丢 preferred 记录。
- 在 adb 会话里 `stop adbd; start adbd` 自杀 → 见坑 B4。
- 装完自启应用不打开就重启 → BOOT_COMPLETED 不投递，白 reboot 一次（坑 B1）。
- 只看 `Success` 返回值不实测 → **验收标准永远是遥控器按键和重启后的屏幕**。

## 4. 会话纪律

- 每一步在设备上留下可查痕迹：`/data/local/tmp/*.log`、应用自己的 `files/boot.log`。
- 改动前后各贴一次 `ls -la` / `getprop` 输出，让人能对比。
- 出事故时：**先恢复连接，再分析原因**。失联状态下任何"我觉得问题在哪"的猜测都不可信。
- 结束后把这次的事故与误判补进 `cases/<你的机型>/`，这是仓库唯一真正稀缺的内容。
