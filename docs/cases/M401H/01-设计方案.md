# 设计方案

## 0. 约束（来自设备主人的明确要求）

1. **不删除、不冻结任何运营商应用** —— 只做"提优先级"。原因：运营商应用的组件（尤其设置里的调试入口）是失联后唯一的自救通道，动它们等于自断后路。
2. **设置应用、遥控热键、官方调试入口绝对不动** —— 调试入口 `设置→密码10086→其他→左键32下` 是最后的安全网。
3. **重启前必须把所有准备做完** —— 这台机器网络 ADB 重启即掉，盲目重启 = 失联。
4. 数据不重要（电视盒子无个人数据），**重点是绝不变砖**。

这四条直接决定了整个方案的形态。

## 1. 侦察结论（一切设计的前提）

| 项目 | 结论 |
| --- | --- |
| 机型 | 浙江移动 M401H，国科 GK6323V100C，board=kunlun，Android 9 (API 28)，armeabi-v7a |
| root | `/system/xbin/su` 存在（setuid root），语法 `su 0 <cmd>`；**但 su 内部有调用方白名单，应用身份被拒**（"not allowed"） |
| SELinux | **Permissive**（avc 只审计不拦截）← 全案基石 |
| 开机 HOME | `com.sumavision.loader/.MainActivity`（SkyLoader 登录页）与 `com.yst.whitebox` 竞争 |
| 网络 ADB | 非持久。开机 `persist.sys.usb.config=none`，adbd 根本不起；靠用户从设置入口手动拉起，重启即失联 |
| 默认桌面记录 | `cmd package set-home-activity` 写入的 preferred activity 数秒内被 PMS 以 "Result set changed, dropping" 作废 —— 该平台此机制不可依赖 |
| init | `/system/etc/init/` 下新增 .rc 文件**不会被解析生效**（实测），不要在此赌运气 |
| 应用广播 | 刚 `pm install` 的应用处于 stopped 状态，**收不到 BOOT_COMPLETED**；打开一次即解除 |

## 2. 总体架构：三层冗余，全部可逆

```
┌─ 目标A：开机直达当贝桌面（登录页消失）────────────────┐
│  SkyLoader 同包名替身（/system/app 原位替换）          │
│   - 登录代码物理上不存在了                             │
│   - onCreate: startActivity(当贝) + finish()          │
│   - HOME intent-filter priority=1 稳赢白盒/其他候选    │
│  TvFix 开机 +25s 发 HOME intent 兜底（经替身转当贝）    │
└───────────────────────────────────────────────┘

┌─ 目标B：网络ADB每次开机自动可用（免root）──────────────┐
│  动态层（主力）：TvFix v4 BOOT_COMPLETED +15s          │
│    SystemProperties.set("service.adb.tcp.port","5555")│
│    SystemProperties.set("persist.adb.tcp.port","5555")│
│    SystemProperties.set("ctl.restart","adbd")         │
│    Settings.Global adb_enabled=1 (priv-app 白名单权限) │
│  静态层：/system/build.prop 追加 service.adb.tcp.port  │
│  应用层兜底：TvFix 桌面按钮②，随点随开                  │
└───────────────────────────────────────────────┘

┌─ 横向保障 ────────────────────────────────────────┐
│  TvFix 以 priv-app 装入 /system/priv-app（防删）      │
│  原版 SkyLoader 双备份（/data/local/tmp + Mac）       │
│  全部应用冻结一键恢复（TvFix 按钮⑥）                   │
│  终极兜底：U盘 recovery 卡刷                          │
└───────────────────────────────────────────────┘
```

## 3. 关键设计决策与被否掉的替代方案

### 3.1 为什么"替换 SkyLoader"而不是"反编译去验证"？
原包反编译后只有 `MainActivity(HOME+LAUNCHER)` + 空 `Application`，没有任何 service/receiver——
**同包名同组件名的替身 APK 可以无损原位替换**，不需要 apktool/smali/重打包原代码，
产物只有 8.6KB，行为完全可控。若原包组件多，则应走 apktool 改 smali 的路线。

### 3.2 为什么 HOME 靠 intent-filter priority 而不是 set-home-activity？
实测该 ROM 上 preferred activity 记录会被系统持续作废（原因未深究，疑似运营商残留逻辑）。
intent-filter 的 `android:priority` 是**包扫描期属性**，不依赖运行时记录，PMS 解析时直接生效。
给替身 loader 设 `priority=1`（候选们都是 0），HOME 解析稳定收敛到替身 → 替身转交当贝。

### 3.3 为什么开机 ADB 走"应用直写属性"而不是 su？
三个事实：
- su 对应用身份直接拒绝（内部白名单，改文件权限位救不了）；
- 该平台 init 不解析新增 rc 文件，init 钩子路线死；
- **SELinux 是 Permissive** —— Permissive 下 avc 拒绝只记录不执行，普通应用调用
  `SystemProperties.set("ctl.restart","adbd")` 会真实生效（init 收到属性变化执行重启）。

于是免 root 路径成立：`写端口属性 → ctl.restart adbd → adbd 启动时读 build.prop 里的 5555 → 监听 TCP`。
辅以 priv-app 身份 + `WRITE_SECURE_SETTINGS` 白名单写 `adb_enabled=1`（走标准调试开启链路，双保险）。

### 3.4 为什么 TvFix 要装成 priv-app？
- 防误删（/data 里的版本清了，/system 的还在，PMS 视为"系统应用被更新"）；
- 配合 privapp-permissions 白名单拿到 `WRITE_SECURE_SETTINGS`；
- 用户侧入口常驻：按钮②免root开ADB / 按钮⑥一键恢复冻结应用，是"失联自助"工具。

### 3.5 被否掉的方案
| 方案 | 否决原因 |
| --- | --- |
| pm disable/uninstall 运营商应用 | 用户明令禁止；且曾实测引发 ADB 失联事故 |
| Magisk | 需要 patch boot 镜像再刷写，GK6323 平台资料少，变砖风险不成比例；本机已有 setuid su，功能重复 |
| init.rc 钩子固化 ADB | 该平台实测不解析新增 rc，死路 |
| set-home-activity 固定桌面 | preferred 记录被系统秒丢，不可依赖 |
| 修改 Dangbei manifest 提优先级重签 | 替身 loader 方案更干净（不动当贝本体） |

## 4. 风险控制

- 每一步 `/system` 写操作前 remount rw，操作后 `sync`；
- 所有替换动作先在设备上留备份（`/data/local/tmp/*_backup.apk`）；
- 不动 `init.kunlun.rc` 等开机关键 rc（语法错误=开不了机，得不偿失）；
- 每次重启前跑检查清单（见执行实录 §终验清单）。
