# 踩坑大全（平台特性 + 可迁移经验）

> 每条都付出过真实代价。适用于：国科/海思方案的运营商 Android 盒子，部分经验通用于所有 Android。

## A. root 与提权

### A1. su 有调用方白名单，文件权限位救不了
- 现象：`/system/xbin/su` 为 `-rwsr-x--- root shell`，应用 exec 报 `IOException error=13 (EACCES)`。
- 误修：`chmod 4755` 后文件可执行了，但 su 输出 **"su: not allowed"** —— su 二进制内部按调用方
  uid/包名白名单放行（本机只放 shell/root 组）。
- 结论：**别指望让应用走 su**。出路：① SELinux Permissive 下直接 SystemProperties（本项目用法）；
  ② 换成应用可用的 su（如 Magisk 授权）——需要 patch boot，风险自评。

### A2. `su` 的语法陷阱
本机 su 是 busybox 风格：`su 0 <cmd>` ✅、`su -c <cmd>` ❌（报 invalid uid/gid '-c'）。
写跨机脚本时两种都试（见 `src/tvfix/.../RootShell.java` 的 attempts 数组）。

### A3. SELinux Permissive 是普通应用的绿灯（本项目的根基）
`getenforce` = Permissive 时，avc 拒绝**只审计不执行**：
- 应用可以 `SystemProperties.set("service.adb.tcp.port","5555")` ✅
- 应用可以 `SystemProperties.set("ctl.restart","adbd")` ✅（init 收到后真的会重启服务！）
- 应用可以执行任意系统二进制（如 busybox）
先 `getenforce` 看一眼再设计提权方案，能省掉一整条 root 链路。

## B. 开机自启

### B1. 刚装完的应用收不到 BOOT_COMPLETED（stopped 状态）
`pm install` 之后应用处于 stopped 状态，**所有广播都被丢弃**（含 BOOT_COMPLETED），
直到它被打开过一次。`pm install -r` 更新是否保留"非 stopped"状态不可依赖——
**装完就 `am start` 一次**，一了百了。

### B2. 该平台 init 不解析 /system/etc/init/ 下新增的 .rc
ROM 自带的 rc（audioserver.rc 等）在那儿工作正常，但**运行期新增的 rc 文件**：
- 开机不解析（实测 trigger 不触发）；
- 开机后再改文件更不会重读（init 只在启动时解析）。
固化"开机做某事"别押注这条路。可靠的是：应用 BOOT_COMPLETED 接收器 + 应用打开过一次。

### B3. build.prop 属性单独不够
`service.adb.tcp.port=5555` 写进 build.prop 后，若 adbd 服务**根本没有被启动**
（本机 `persist.sys.usb.config=none`，开机不拉 adbd），属性写得再对也没人读。
属性负责"监听哪个端口"，**还得有人负责把 adbd 启动起来**（ctl.restart / adb_enabled 链路）。

### B4. 永远不要在 adb shell 会话里 `stop adbd`
adbd 一死，挂在它下面的 shell/su 全部陪葬，`start adbd` 永远执行不到，直接失联。
要重启 adbd：从应用进程里做（TvFix 的做法），或者 `nohup sh -c 'stop adbd; start adbd' &`。

## C. 默认桌面（HOME）

### C1. preferred activity 记录可能被系统持续作废
`cmd package set-home-activity` 返回 Success ≠ 生效。本机日志：
`PackageManager: Result set changed, dropping preferred activity for Intent {HOME}`，
`resolve-activity` 永远显示 ResolverActivity。
**但真实 HOME 键行为不受影响**（候选排序仍在工作）——别被探测命令误导，要实测按键。
固化方案用 `intent-filter android:priority`（包扫描期属性，不依赖运行时记录）。

### C2. 替身启动器：比反编译更干净的去登录方式
若运营商 HOME 只有一个入口 Activity（用 `aapt dump xmltree` 确认），可自建**同包名同类名**
的迷你 APK 原位替换（备份原版 + 删 oat 目录防 odex 校验），登录代码物理消失。
比 apktool 改 smali 重打包省掉一整层工具链，签名自由。

### C3. 系统应用原位替换注意事项
- 替换前备份到 /data/local/tmp（/system 是 ro，先 remount rw）；
- **删掉 APK 同目录的 oat/**（旧 odex 与新 APK 的 dex 校验和不匹配）；
- chmod 644 + chown 0.0 + restorecon + sync；
- 重启后 PMS 重新扫描（签名变化对"被替换的系统应用"是合法的全新扫描）。

## D. 开发与部署

### D1. 这台机器 `adb install`（streamed）是坏的
报 `failed to stat`。用 `adb push` 到 `/data/local/tmp` + 盒端 `pm install -r` 代替。

### B/D2. shell 读不了 /system/build.prop（Permission denied）
排查 build.prop 内容要用 `su 0 grep`。别被 shell 的 ENOENT/EACCES 假象骗了。

### D3. 从卡刷包提取 APK 的完整链路
`update.zip` → `system.new.dat.br` →(python brotli)→ `system.new.dat`
→(sdat2img + transfer.list)→ ext4 raw image →(python `ext4` 库)→ 按路径取文件。
坑：ext4 dirent 的 name 字段带垃圾填充字节，必须清洗后再查 inode（脚本已处理）。

### D4. 无 Gradle 快速构建 APK
aapt2 link（仅清单无资源）→ javac --release 8 → d8 → zip 塞 classes.dex → zipalign → apksigner。
5 个命令构建一个 TV 应用，CI 或应急都好用（见 `scripts/build_apk.sh`）。

### D5. 诊断要打日志文件
应用的 shell 执行结果 UI 上转瞬即逝（tv 盒子连截屏都麻烦）。让接收器把每步输出写
`/data/data/<pkg>/files/boot.log` + 脚本侧写 `/data/local/tmp/*.log`，adb 一拉就真相大白。
v3 加了日志后，"su: not allowed" 一行就推翻了之前所有假设。
